# v0.2.0-alpha.2

设备读卡后可能停留在 READER 模式：A/B 切槽没有恢复模拟，学习模式又阻止深度休眠，使设备一直保持该状态。现在物理 A/B 选择会加载该卡后恢复 TAG 模式；最后一个 USB／BLE 管理连接关闭且场发生器未启用时，也自动恢复模拟。进入读卡模式会清除被中断的模拟场，避免缺少离场回调时一直锁住切槽和休眠。USB 拔出会清除过期的串口打开标志，连接中的 GUI／CLI 读卡模式仍正常保留。

AUTO／OBSERVE 恢复官方空闲休眠。入睡前停止扫描、保存脏模型；手动锁定通过官方保留 RAM 跨睡眠保存，并在冷启动丢弃。活动场阻止普通休眠，低电量关机不受模型保存失败阻止。深度休眠期间不扫描环境；直接由 RF 唤醒时先使用保存的当前卡。

RF 场中立即停止被动扫描，NFC 接收先准备就绪；学习采样移至官方回应设置之后。硬件 HF 场检查补充软件场标志，保护切槽、写模型与休眠。

保留 alpha.1 的 USB 描述符修正、官方协议 2.2、CLRN v1 模型和官方卡片布局。官方源码基准仍为 2026-10-07 的 ChameleonUltra `5c99d4a39b424cc67ae82bbcfc8ba5ec8f69bf9c`，包含 4K 卡块处理修复；源码来源及补丁清单见 UPSTREAM_SYNC.json。

验证：主机运行时和平台适配回归、内存检查、CLI／签名／上游文件完整性测试，ARM 构建及 HEX／DFU 校验。本次按要求未烧录，外部读卡器刷卡、实际休眠功耗和唤醒兼容性待实体设备验收。alpha.1 的 32 次密钥认证属于设备作为读卡器的验证，不能替代模拟卡在外部读卡器的验收。

升级仍应备份卡片；签名 ZIP 仅更新应用，保留引导程序、SoftDevice 和 FDS。普通升级不替换官方引导程序，也不自动迁移旧 v0.1.0-alpha.2／alpha.3 私有卡片格式。生产目标是 Ultra HW v1，Lite 不适用。
