# Ultra 安装、迁移与验收

alpha.2 已修复 A/B／管理连接关闭后恢复模拟和 AUTO 空闲休眠。2026-10-08 已在 Ultra HW v1 上烧录，回读版本、两张卡的数据和设备设置一致，关闭串口后自动恢复模拟已验证。用户反馈外部读卡器刷卡及自动休眠测试没有问题；休眠电流、RF 唤醒及跨休眠手动锁定仍应按自己的硬件实际验收。验证记录见 [v0.2.0-alpha.2.json](verification/v0.2.0-alpha.2.json)。

v0.2.0-alpha.2 沿用 alpha.1 同步的 2026-10-07 官方基准，目标为量产 Chameleon Ultra HW v1 / nRF52840 / S140 7.2.0。签名 ZIP 只更新应用，不更换引导程序／SoftDevice，不擦除 FDS。Lite、旧原型机和更换了公钥的引导程序不适用。

## 安装

1. 保存自己的卡片 dump、LF ID、昵称、启用状态、防冲撞参数和配置，并保留可刷回的应用 ZIP。从 v0.1.0-alpha.2／alpha.3 升级需先导出其私有卡片数据，再按现行官方协议导入；旧私有记录仍保留，但不会自动解释成官方记录。CLRN 学习模型格式保持不变。
2. 使用本次构建的 `ultra-dfu-app.zip`，核对同一 manifest 的 SHA256。HEX／BIN 不含 DFU 签名，不能当作应用 ZIP。
3. 用当前 GUI／CLI 进入 DFU，或按官方按键流程进入。学习 CLI 支持 `enter-dfu`；对立即复位且无 ACK 的旧官方应用使用 `enter-dfu --official`。
4. 使用 Nordic nrfutil 或支持本地 ZIP 的工具烧录：`nrfutil device program --firmware ultra-dfu-app.zip --traits nordicDfu`。
5. 重启后读取版本、型号和协议；macOS 如需配件允许，解锁后重新连接 USB 并允许。连接本项目 CLI 所需依赖为 `software/script/requirements-learning.txt`。
6. 恢复备份卡片，校对回读数据，然后切回模拟模式。新模型默认 AUTO，已有保存模式保留；需要启用可执行 `mode auto`，观察可执行 `mode observe`，关闭可执行 `mode off`。

DFU application_version 保持官方值 1，以保留刷回官方应用的能力。卡片／配置／模型没有跨记录事务，修改和导入后保存，避免在保存前断电。

## 实体设备验收

- 回读自定义版本、2.2 管理协议、Ultra 型号、硬件序列号及官方命令能力。
- 同一 Classic 1K 测试卡应显示 16 个扇区（0–15），验证卡型、默认密钥检查及适用的恢复流程；Mini 本来只有 5 个扇区。
- 恢复备份卡槽，回读比较 dump、防冲撞参数和昵称。切回模拟模式，用自己的读卡器检查实际刷卡；“接口存在”不代表成功恢复或实际读卡器通过。
- 关闭串口时观察 USB 空闲／充电呼吸灯，连接时检查官方 USB 动画。
- 按 A/B 后等待超过 30 秒再刷卡，整次刷卡不能被自动推荐覆盖；离场后检查手动选择产生的样本。无按键、已有可靠场景时检查自动预选；无匹配时保持当前槽。
- HF/LF 场中禁止切卡；场中按键请求离场后应用于下一次刷卡，不将旧交互误标为新卡。
- 断电重启检查卡片、昵称及模型恢复；UTC 须重新同步。射频稳定性、续航和多读卡器匹配需长期实测。

卡片 dump、ID 和密钥仅存入自己的本地备份，不应提交到公共 GitHub 仓库。
