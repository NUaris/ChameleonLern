# 混合学习实现

## 采集与学习

设备端纯 C 核心不需要网络、云模型、浮点或动态内存。每个上下文最多保存 6 个蓝牙标识、8 个读卡器 token 和本地星期／分钟。最多 32 个样本，各自关联一个卡槽及重复反馈计数。

公共或静态随机 BLE 地址使用 32 位哈希。旋转隐私地址不直接进入模型；可用完整／缩略名称（至少 4 字节）、128 位 UUID、iBeacon UUID+major+minor、Eddystone UID 形成稳定线索。厂商 ID、通用 16 位服务编号本身不足以区分设备，不单独使用。哈希可能碰撞，多个设备也可能发送相同名称；候选冲突门槛能减少误切，不能消除所有误判。

RSSI 使用 `(3×旧值+新值)/4` 平滑，缓存只保留 20 秒。超出容量时替换最弱信号，过期条目优先回收。

HF 中断只记录有界的 token：`kind:5 bit + parameter:8 bit + timing:3 bit`。kind 为寻卡 1、级联 2、认证 A 4／B 5、RATS 6。parameter 取 WUPA 标志、级联／NVB、块号或 RATS 参数。时序为最近命令之间的粗粒度间隔；连续同类同参数 polling 去重。学习模型不保存 UID、密钥或认证 nonce。原固件的独立认证日志仍属于原功能。

HF 离场后，主循环将命令前缀与当时尚未过期的 BLE／时间合为最近会话；20 秒内可用明确反馈绑定到正确卡槽。此时环境／时间取离场处理时的快照。LF 只参与有场保护，尚无读卡器身份特征。

观察／自动模式下的按钮或模拟模式手动选择学习当时环境；读卡模式的配置选槽不产生标签。`train` 允许明确确认当前环境或最近读卡会话。自动选择不生成训练标签。相同卡槽、相同特征可用性且相似度至少 85 的样本合并，反馈计数饱和于 255；满容量时替换最旧样本。用户纠正冲突时可清除原槽历史。

## 评分与切换

BLE 对共有标识按 RSSI 差距扣分，再以标识并集数量归一化；读卡器对命令前缀匹配，时序桶变化允许折扣。时间按一天中的循环距离衰减，3 小时后为 0；不同工作日给折扣，工作日／周末不一致进一步降权。只采用双方均存在的特征并归一化权重。

时间不能独立提供身份依据；蓝牙相似度需至少 50，或读卡器相似度至少 70 且包含认证／RATS token。各卡槽取最匹配的样本，默认总分至少 70、领先第二候选至少 12、该样本至少 2 次反馈。

只在模拟模式、AUTO 模式、无 HF/LF 场、离场至少 350 ms、手动保护期 30 秒已过、自动切换保护期 10 秒已过时切卡。OBSERVE 输出建议但不自动切换。切换前停止监听并保存原卡 RAM 数据；目标记录缺失、长度不符或配置异常时清空旧回调／缓冲并回退原槽。Flash 失败不得提前更新已保存 CRC。

读卡器通信开始之后才能提取相关特征。因此不会承诺“未知读卡器第一次触场时即时换卡”：正在进行的交互始终锁卡，离场后的建议用于下一次刷卡，BLE 可在触场前预选卡。

## 持久化与资源

FDS 模型记录 file=`0x4C10`、key=`1`，固定 2208 字节，独立于官方及本项目卡槽和卡片记录。卡槽配置 file=`0x4C00`、key=`1`；HF/LF dump 分别使用 file=`0x4C01/0x4C02`、key=`1+slot`。编号统一见 `storage_ids.h`。此隔离布局从 alpha.2 开始，不自动解析现行官方或 alpha.1 的历史卡片／模型记录；升级前备份，升级后重新导入和学习。

模型编码为大端，开头 `CLRN`、版本 1、长度、CRC32、配置与样本；不直接持久化编译器结构。校验／版本／长度失败时保留默认 OFF 模型。修改后标记 dirty，每 30 秒在空闲时保存；失败同样退避 30 秒并保留 dirty；`save` 允许显式保存。

模型与卡槽配置是不同 FDS 记录，没有跨记录事务。导入会先写默认记录并在 RAM 分块修改，失败保持读卡模式，重新执行完整导入。成功保存完成后恢复模拟。断电前还没有完成保存的反馈或卡片 RAM 修改可能丢失。

GCC 应用范围为 Flash `0x27000..0xc7000`、RAM `0x20006000..0x20038000`；保留日志区 `0x20038000..0x20040000` 不参与 BSS 清零。FDS 22 个 8192 字节虚拟页在安装基线 `0xf3000` 引导程序时占用 `0xc7000..0xf3000`。链接器及 HEX 校验拒绝应用越界。

时间由 UTC 同步、时区偏移与运行计时组成。时钟有效性不会保存为跨重启的绝对时间，防止把停机前的时刻当成当前时刻；重新开机需校时。扫描模式保持 System ON，功耗与射频稳定性应按实体硬件测量。
